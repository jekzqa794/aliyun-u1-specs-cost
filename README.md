## u1适合什么业务，哪些场景要避开

u1为通用场景设计，官方列的适用方向包括Web应用及网站、企业办公类应用、数据分析和计算。落到具体业务就是：企业官网、中小型Web应用、APP应用服务器、轻量级数据库（MySQL）、缓存（Redis）、搜索集群、内部OA/CRM系统，以及开发和测试环境。业务处于起步或稳定期、没有极端高并发需求，u1的均衡配置足够撑住。

有两类场景官方明确建议绕开u1：

- 依赖高算力提供极致体验的场景，比如游戏服务器和高频交易，这类业务建议直接上c7/g7/r7；
- 对性能一致性有强诉求的场景，典型的是HA主备架构——主备机需要性能一致。

第二种经常被忽略，原因值得展开说：u1实例创建时会被随机部署到不同的服务器平台，生命周期中还可能迁移平台，不同平台之间可能存在明显的性能差异。日常单机业务几乎感知不到，但主备机一旦分别落在不同平台，切换时就可能出现性能落差。有HA需求的话，选c7/g7/r7这类性能一致的企业级实例更稳妥。

## 购买u1前要确认的5个限制

1. **CPU型号不能指定**：8163或8269CY由平台随机分配，部署在哪个服务器平台也无法选择；
2. **系统盘只支持ESSD类云盘**，更低价的云盘类型不在选项里；
3. **仅支持专有网络VPC**，经典网络用不了，IPv6是支持的；
4. **变配只能在u1规格族内部进行**，想换成c7/g7/r7等其他家族，得通过迁移的方式；
5. **数据盘数量有上限**：ecs.u1-c1m8.xlarge及以下规格最多挂8块，2xlarge及以上规格可挂16块。

这几条里对后续影响最大的是第4条。如果预期业务一年内要升到更高性能档位，购买前就想清楚是留在u1家族内升配，还是一开始就选u2i或u2a。

## 常见问题

**199元活动有什么购买条件？**
这类低价长效特惠通常对账号资格有要求，比如限新用户或未参加过同类活动的账号。下单前以活动页显示的到手价和规则说明为准。

**2核2G和2核4G的u1怎么选？**
主要看内存压力。跑数据库、缓存或者单机部署多个服务，2G内存很快见底，1:2配比的2核4G是通用场景里适用面最广的选择；纯静态站点、轻量脚本，2核2G也够用。

**u1支持IPv6吗？**
支持。网络方面仅支持专有网络VPC，新建实例默认就在VPC里，一般不需要额外操作。
